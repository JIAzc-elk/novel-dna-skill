# 网文写法蒸馏器（novel-dna-skill）

> **一句话**：把你喜欢的一部网络小说拆成一套「能照着写的说明书」，然后拿这套说明书去改写你自己的稿子，或者按大纲续写新章。

一个给 AI 用的 Skill（技能包），专治两件事：

1. **AI 改出来的小说有味儿**——满篇「指尖」「垂眸」「眼底闪过一丝异样」「不是 A，而是 B」「雨还在下，青石地被洗得发亮」。
2. **AI 改完还是像原稿**——因为它一边看着你的原稿，一边逐句换近义词，原稿的骨架一点没变，检测器一抓一个准。

## 它到底做了什么

分三步走，全程离线，不联网、不要 API Key：

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| **① 蒸馏** | 读你提供的原文章节，量化它的句法、段落、虚词、标点习惯，挑出最有代表性的场景切片，提炼成一条条**带原文引用**的规则 | 一个「写作包」目录 |
| **② 校验** | 每条规则都必须能在原文里**逐字查到**那句话，查不到就报错；场景行号、文件哈希、覆盖缺口也一起核对 | `PASS / FAIL` 报告 |
| **③ 改写或续写** | 调用写作包，先剥离原稿的句子骨架，再按那本书的真实笔法重写；写完跑本地「反 AI 味」门禁 | 成稿 + 检测报告 |

蒸馏出来的东西长这样（`写作包/书名写作包/`）：

```
PACK.md              ← 总入口：这本书最鲜明的十个写法 + 场景路由表
指纹/语言与节奏.md   ← 长短句怎么呼吸、什么词是这本书的口头禅
指纹/人物对白与势力.md
指纹/战斗与设定.md
指纹/日常与职业.md
指纹/修辞用典与信息.md
指纹/情绪与主题.md
rules.jsonl          ← 每条规则都挂着原文行号和逐字引文
scenes.jsonl         ← 段落级场景切片，写作时精准调阅
stats.json           ← 句长均值/标准差、单句成段率、标点分布…
corpus/              ← 原文副本（只在你本地，用于校验）
```

## 三种用法

### 用法一：蒸馏一个写作包

**你需要提供**：一章、几章，或者一整卷原文（txt / md 都行，越多越准）。**没有最低章数门槛**，给 1 章就拆 1 章。

```
把这些章节蒸馏成《蛊真人》写作包
```

它会：

1. 建目录、复制语料、算哈希、跑一次语言学统计；
2. 逐章记录**写法观察**（不是剧情梗概）；
3. 切出段落级「黄金场景」切片（禁止把整章打包成一个切片）；
4. 提炼出带原文引用的规则；
5. 最后告诉你：**现在这个包还缺哪些场景**（例如「缺少小人物向上位者求情的对话样本」），让你按需补充。

### 用法二：改写已有正文（最常用）

```
用《蛊真人》写作包改写这篇正文
```

**必须守住**：剧情因果、人物性格、账目数字、各方知情范围、结局走向。

**完全放开**：段落顺序、插叙位置、详略比例、句子结构、增删细节。

所以它会把「他先回忆了三百字前世，然后管事才进来催账」直接掰成「管事一进门就在催账，前世的记忆插在他给管事递台阶的那一刻」。这不是偷懒，是因为**顺序本身就是 AI 味的来源之一**。

### 用法三：按纲要写正文

```
用《蛊真人》写作包按这个纲要写第四章
```

纲要里的事件、手段、胜负、章末落点严格落地；普通环境、动作回合、对白措辞自主补全。只有当纲要缺了**决定动机/破局机制/结局走向**的关键前提时，它才会先问你。

## 改写前后的真实差别

**改写前**（典型的 AI 初稿腔：开头先报天气和主角简历，一句一段碎成电报体）

> 长青庄的雨下了一夜，天亮时还没停。
> 魏家外院的青石地被水泡得发黑，廊下挂着一排湿漉漉的蓑衣。厨房那边早起烧火，烟顺着瓦缝压下来，混着米汤味、草药味，还有后院马棚里潮热的粪气。
> 陈立坐在账房门槛里的一张高凳上。
> 凳子是给大人坐的，他脚尖悬着，够不着地。人也瘦，十二岁的身量，穿一件洗得发白的灰布短袍，袖口短了一截，露出两截细腕子。
> 腕子上有几道旧疤，像被荆条划过。

**改写后**（直接开场进冲突，外貌细节延后随动作带出）

> 「陈立，动作快一些！内院今天要派人来查仓，少爷书房那边也等着你过去磨墨。」
>
> 长青庄外院的账房门口，管事魏福拿一根没点燃的旱烟杆敲了敲门框，出声催促道。
>
> 外面大雨倾盆，从昨夜一直下到天亮都没有停歇。因为水气太重，桌案上摊开的米粮、皮货和药材三本账册都已经受潮发软。
>
> 陈立坐在桌案后的高凳上，拨动桌上的竹筹，开口道：「米粮的账目不对，少了三斗二升。」
>
> 「胡说！」魏福脸色顿时一沉，「这批粮昨天才刚刚入库，怎么可能平白无故就少了？」

改动不在辞藻，在结构：

- 删掉了无后续因果的气味清单（米汤味、草药味、粪气）；
- 把「年龄/衣着/旧疤」的简历式盘点拆散，挪到后面跳下高凳、藏麦饼时再带；
- 把「他脚尖悬着，够不着地」这种一句一段的电报体，合并成正常叙述；
- 对话和算账提上来，冲突在第一行就开始。

## 为什么它比"让 AI 直接改"强

### 1. 它量化的是「这本书怎么写字」，不是通用写作常识

每个写作包都会统计出这本书的机械基线，例如某本书实测：

| 指标 | 实测值 | 意味着什么 |
| --- | --- | --- |
| 句长均值 / 标准差 | 20.93 字 / 11.75 | 正常网文的句长是**离散**的，不是均匀的 |
| 单句成段率 | 57.36% | 一半以上段落只有一句话 |
| 分号使用 | 61 万字里只有 6 次 | 白话叙述基本不用分号 |
| 引号内文本占比 | 27.61% | 对白占比高 |

这些数字会变成写作时的硬约束，而不是「请写得口语一点」这种废话。

### 2. 它逼你摆脱原稿骨架

改写时**不许看着原稿逐句换词**。因为实测发现：只要保持原稿的分句顺序，哪怕把每个词都换掉，检测器依然认得出来。

正确做法是先抽成「谁在场 / 发生了什么 / 数字是多少 / 埋了什么伏笔」的**裸事实清单**，再脱离原稿句子重写。

### 3. 它有一道本地门禁，专抓 AI 的招牌动作

`scripts/check_novel_ai.py` 是个纯 Python 的确定性扫描器，不需要联网模型。它拦的是这些：

| 拦截项 | 抓的是什么 | 为什么 |
| --- | --- | --- |
| `machine-opening-inventory` | 开头第一段同时报天气 + 报主角年龄/衣着/伤疤 | 大模型最强的开篇指纹 |
| `clue-recap-list` | 章末把前文线索用顿号排比重列一遍 | AI 阶段性总结癖 |
| `embodied-simile` | 「针扎似的凉意」「胸口像被冷针扎」 | 给情绪和感官硬加比喻 |
| `dropped-numeral` | 「蹿起阵」「泛起股」 | 为躲正则把「一」抠掉留下的语病 |
| `fake-folksy-dialect` | 「今儿」「里头」「瞅着」扎堆 | 靠儿化音假装口语 |
| `excess-zhe-posture` | 「敞着」「叼着」「盯着」泛滥 | 伴随状态词密度超标 |
| `plain-function-starvation` | 但是/因为/虽然/现在/可以 全被删光 | 压缩成伪古风，反而更像机器 |
| `bookend-weather-ending` | 章末摸一下道具 + 写天气收尾 | 首尾呼应打卡 |
| `source-phrase-retention` | 与原稿 3 字/5 字片段重合率过高 | 抓逐句同义改写 |
| `bloated-sentence-length` | 平均句长过长 | 抓把多句话拿逗号硬焊 |

**关键点：这些阈值是拿真实人类网文反向校准出来的**，不是拍脑袋定的。实测 193 章真人原著里 93% 以上的章节能自然通过——意味着它不会把正常的人话判成 AI。

## 反 AI 味的底线：好看第一

这个 Skill 有一条最高裁决原则写死在 `SKILL.md` 里：

> **「读起来好看、像真人老手写的网文」永远排第一，检测率排第二。**

原因是实证过的：如果为了刷某个统计指标去硬改，模型会造出更糟的东西。比如为了躲「像」字，把「胸口像被冷针扎了一下」改成「心口猛地蹿起阵针扎似的凉意」——语法都不通了，AI 味反而更重。

所以门禁只拦**真正损害阅读质感**的东西，不追求把每项指标压到极限。

> 另一个实话：如果你的底稿本身就是 AI 写的，它的场景切分和事件节拍带有原生的模型结构痕迹。在「剧情不许改」的前提下，能做到顶部评级为「人工创作特征显著」、粉色高危占比归零，但要求一万字切成十几段**全部**落在最低风险区间，任何离线工具都做不到——包括人类作者写的常规过场段，也可能被标成「疑似」。

## 命令行工具速查

只依赖 Python 3.10+ 标准库，无需任何第三方包。

```bash
# 1. 建包：扫描语料、算哈希、生成 stats.json
python scripts/novel_pack.py init --name 我的写作包 --output 写作包/我的写作包 --input <章节文件或目录>

# 2. 增量补充新章节（已有分析保留，状态回退为 draft）
python scripts/novel_pack.py add --pack 写作包/我的写作包 --input <新章节路径>

# 3. 重算语言学统计
python scripts/novel_pack.py stats --pack 写作包/我的写作包

# 4. 按名字或别名找包
python scripts/novel_pack.py find --root 写作包 --name 我的写作包

# 5. 写作前调阅黄金场景切片
python scripts/novel_pack.py slice --pack 写作包/我的写作包 --scene S004 S005
python scripts/novel_pack.py slice --pack 写作包/我的写作包 --tag 地位差对白 --limit 3

# 6. 严格校验（哈希、引文逐字匹配、场景行号、覆盖声明）
python scripts/novel_pack.py validate --pack 写作包/我的写作包

# 7. 反 AI 味门禁（改写模式记得带 --source）
python scripts/check_novel_ai.py 成稿.md --source 原稿.md --output .work/ai_check.json
```

跑测试：

```bash
python -m unittest discover -s tests -v
```

## 常见问题

**Q：一定要给 193 章吗？**
不用。给多少就拆多少，1 章也能出包，只是覆盖的场景会少。蒸馏完它会主动告诉你缺什么（比如「缺少逆风逃亡战的样本」），你再按需补。

**Q：能用来写原创，不只是改写吗？**
能。用法三就是「按纲要写正文」。它会守住纲要给定的事件与胜负，自主补全过场、对白、心理推演。

**Q：会不会把原著的角色、蛊虫、门派名硬塞进我的故事？**
不会，这在 `SKILL.md` 里是明令禁止的红线：蒸馏的是**手法**（怎么算账、怎么递台阶、怎么破招），不是**设定**。

**Q：需要联网或付费 API 吗？**
不需要。蒸馏、校验、扫描全靠本地 Python 标准库。

**Q：检测器一定能过吗？**
不能保证，也没有任何工具能保证。它做的是**把已知的高危模式压下去**，并且用真实人类网文的统计基线做校准，避免误伤正常表达。最终效果受你的底稿质量、题材、篇幅影响很大。

**Q：中文繁体、英文小说能用吗？**
维度体系通用，但反 AI 味门禁的阈值是拿简体中文网文校准的，其他语种需要自己重新标定。
