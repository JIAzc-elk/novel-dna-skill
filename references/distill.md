# 小说语料蒸馏与增量更新流程（distill.md）

本指南规定如何将用户提供的小说章节蒸馏为高可用、可验证的命名写作包（如 `写作包/蛊真人写作包/`）。

---

## 一、核心原则：给多少蒸馏多少，重质不凑数

1. **输入范围完全服从用户**：
   - 用户给 1 章、6 章、193 章或几个片段，就只蒸馏这些正文；**不设最低章数门槛**。
   - **严禁私自扩充语料**：不自动读取用户未指定的相邻章节、整本全文或联网搜索书评/百科来冒充已读语料。
   - 目录中的写作教材（如《故事》《人物》《对白》）、旧分析报告、说明文档只作为分析方法参考，绝不混入 `corpus/` 充当目标小说原文。
2. **深度拆解优先于机械走流程**：
   - 脚本统计（`stats.json`）和 JSONL 索引只是骨架；写作包的灵魂在于**真正读透原文每一场戏是如何调度的**，并把它们写成模型下笔就能照着用的**句法配方、场景结构模板、黄金段落解剖与正反例对照**。

---

## 二、标准蒸馏六步法

### Step 1：初始化包、语料含金量预检与表层语言统计（`init` & `stats`）

运行本地助手收集明确选定的 `.md / .txt` 语料：

```bash
python scripts/novel_pack.py init --name "<书名>写作包" --output "写作包/<书名>写作包" --input <章节路径...>
```

- **语料含金量与偏科预警（必做）**：
  - 用户随手选取的章节（如某书开局前 5 章或连续几章赶路过渡章）很可能**严重偏科**（例如只有新手村挨打与面板介绍，完全没有核心势力博弈、代表性克制战斗或高潮戏）。
  - 模型在快速扫读后，若发现语料场景单一，虽照常完成当前语料蒸馏，但必须在交付开头**高亮提示“语料偏科预警”**，明确指导用户从原书中挑选哪几类高含金量章节（立人设开局章、以小博大谈判章、机制克制战斗章、卷末大高潮章）做增量补充。

- 脚本会自动将原文复制到包内 `corpus/C0001.md` 等位置、计算 SHA-256 哈希，并生成 `stats.json`。
- 读取 `stats.json`，重点提取以下 **L1 语言基线指标**：
  - **句长分布**：`sentence_chars.mean`（均值）、`sd`（标准差，衡量长短句起伏幅度）、`short_le_10_share`（≤10字短促定格句占比）、`long_ge_40_share`（≥40字长复句推演占比）。
  - **段落节奏**：`paragraph_chars.mean`、`single_sentence_share`（单句成段占比，直观反映网文换行呼吸感）。
  - **对白与引文占比**：`quoted_char_share`（含对话、带引号独白与引用）。
  - **高频标志词率**：`markers_per_10k_chars`（如 `不是/而是`、`其实`、`然而`、`不过`、`顿时`、`忽然`、`果然`、`居然`、`若是` 等每万字频次）。

### Step 2：分批通读与建立精准场景切片（`analysis.jsonl` & `scenes.jsonl`）

按章节顺序分批通读 `corpus/` 中的原文，完成两项记录：

1. **逐章观察记录（`analysis.jsonl`）**：
   - 每份输入对应一条记录：`{"source_id": "C0001", "sha256": "...", "observation": "...", "rule_ids": [...], "unresolved": [...]}`。
   - `observation` 必须写清**本章的叙事切入点、核心冲突推进手法、视角与信息差调度、收束方式**，严禁写成单纯的剧情梗概。
2. **段落级黄金场景切片（`scenes.jsonl`）**：
   - 将章内最具代表性的交锋、战斗、算账、用典、高潮或日常片段切出精确行号区间：
     ```json
     {"id": "S004", "tags": ["地位差对白", "妥协与威胁", "势力约束"], "summary": "古月漠尘与漠颜开碎尸木盒，从放置后门与木盒尺寸拆解方源既求和又威胁的双层算计，并拍板四项善后处置", "spans": [{"source_id": "C0004", "start_line": 14, "end_line": 58}]}
     ```
   - **切片铁律**：除非整篇输入本身就是不足 40 行的短片段，否则**严禁把整章从第 3 行到最后一行直接当成一个 `scene`**！长章必须切到真正可作为写作范本的段落区间（通常 15~80 行），以便写作时快速调阅校准语感。

### Step 3：提炼有原文铁证的可执行规则（`rules.jsonl`）

对照 `references/dimensions.md` 的六大层次（九个细分维度：`语言与叙述`、`场景与节奏`、`人物与对白`、`博弈与关系`、`战斗与行动`、`世界与题材`、`修辞与用典`、`信息与连载`、`情绪与主题`），提炼规则写入 `rules.jsonl`。

每条规则必须包含：
- `id`：如 `R001`
- `dimension`：所属维度
- `claim`：一句话核心技法命题（必须具体，拒绝常识废话）
- `when`：触发前提（在什么人物关系、战局或信息条件下使用）
- `do`：**分步执行动作**（先写什么→再插什么判断→最后怎么落回现场）
- `effect`：产生的具体阅读体验与叙事张力
- `avoid`：迁移禁区（什么场景不能硬套、如何防止篡改用户原剧情）
- `strength`：`repeated`（跨多个独立场景反复验证）、`local`（特定场景有效）或 `tentative`（待更多样本验证）
- `evidence`：至少 1 处（`repeated` 建议 2 处以上）精确到 `source_id`、`start_line`、`end_line` 及逐字匹配的原文 `quote`
- `counterevidence`：主动寻找原著中反向写法的证据（防止把局部写法吹成死板教条）

### Step 4：编写高密度分层指纹文档（`指纹/*.md`）

参考 `templates/pack-zh/`，根据本批有证据的维度生成对应的 Markdown 指纹模块（如 `指纹/语言与节奏.md`、`指纹/人物对白与势力.md`、`指纹/战斗与设定.md`、`指纹/修辞用典与信息.md`、`指纹/情绪与主题.md`、`指纹/日常与职业.md`）。

**每个指纹模块必须达到以下质量标准（拒绝水货）**：
1. **核心句法与叙事配方**：列出该维度下的 `Rxxx` 规则组合，并提炼出 3~5 个**可直接套用的句式/段落公式**。
2. **场景推进结构模板（Step-by-step Beat Sheet）**：把该类场景（如“以小博大谈判”、“能力克制与真元消耗战”、“识货验物与算账”、“寓言嵌套与回场”）拆解成 4~5 个清晰步点，标明每一步写什么。
3. **原著黄金段落解剖**：直接引用 1~2 段 `corpus/` 中的精彩原文，逐句剖析作者是如何换视角、藏潜台词、算筹码或卡节奏的。
4. **迁移改写示范（Before / After）**：给出一段平庸白水文/大纲，展示如何不改剧情事实、仅用本模块技法将其改写出目标小说的老辣质感。

### Step 5：编写总控入口与覆盖缺口诊断（`PACK.md` & `coverage.json` & `缺口与补充建议.md`）

1. **`PACK.md`（写作包总控台）**：
   - 写明调用名、实际分析的章节范围、L1 语言量化特征速览、最鲜明的十条核心技法、**按任务场景检索表（写什么戏→读哪个指纹模块→查哪几个 `Sxxx` 原文切片）**，以及迁移红线。
2. **`coverage.json` 与 `缺口与补充建议.md`**：
   - 将“本批已充分观察（`observed`）”、“仅有局部样本或上下文不全（`partial`）”、“完全未见（`unobserved`）”区分清楚。
   - **主动向用户提出具体补充请求**：不要泛泛说“请补充更多章节”，而要具体指出缺什么场景，例如：
     - *“当前语料多为上位者内部训诫或生死搏杀，缺少**小人物向陌生大人物当面求取/谈判、且双方都不撕破脸**的完整对话场景；若后续需写此类戏份，建议补充 1~2 章对应正文。”*
     - *“当前仅有伏笔揭底章，缺少**同一伏笔在几十章前首次埋设时如何伪装成日常闲笔**的前置章节。”*

### Step 6：运行校验与交付（`validate`）

1. 将 `manifest.json` 中的 `status` 设为 `"ready"`，并核对 `modules` 列表完整。
2. 运行校验命令：
   ```bash
   python scripts/novel_pack.py validate --pack "写作包/<书名>写作包"
   ```
3. 确认 `"status": "PASS"` 且 `errors` 为空后，向用户汇报写作包路径、核心指纹亮点及可补充的场景建议。

---

## 三、增量更新流程（`add`）

当用户后续提供补充章节以填补缺口时：
1. 运行 `python scripts/novel_pack.py add --pack <包路径> --input <新章节>`。脚本会自动保留旧 `corpus`、`analysis`、`rules` 和 `scenes`，仅导入新文件并将状态回退为 `"draft"`。
2. 只通读新增的 `Cxxxx` 文件，追加 `analysis.jsonl` 与 `scenes.jsonl`。
3. 检验新材料是否印证、修正或新增了 `rules.jsonl`，同步更新对应的 `指纹/*.md` 模块、`PACK.md`、`coverage.json` 与 `缺口与补充建议.md`。
4. 重新运行 `validate` 通过后，将 `status` 恢复为 `"ready"`。
