# 调用写作包：保剧情深度改写与按纲要创作（write.md）

本文件规定如何调用已蒸馏的“小说写作包”完成**已有正文改写**与**章节纲要转正文**。
核心铁律：**锁死叙述人称（改写跟随原稿，按纲要新写一律第三人称）与原稿剧情事实，拒绝同义词降重与胡乱注水，用目标写作包的真实分镜调度与句段呼吸重写叙述肌理！**

---

## 一、动笔前的三步强制校准

用户指定“使用某某写作包”时，严禁凭空捏造文风，必须先完成以下三步：

### 第一步：定位写作包并读取对应指纹模块
1. 使用 `novel_pack.py find` 或直接在 `写作包/` 目录下查找匹配的 `manifest.json`（核对 `name` 或 `aliases`）。
2. 读取 `PACK.md`、`stats.json` 与 `coverage.json`，明确**该目标作品自己的句法与分段基线**：
   - 看 `narrative_sentence_chars`（叙述句均值与标准差）和 `paragraph_chars.single_sentence_share`（单句成段率）；
   - **严禁拿通用标准篡改目标写作包的句段基线**：若目标包单句成段率高达 60%+（如冷硬断奏风），成稿必须保持高频单句成段的铁锤断奏感，绝不把短段落强行焊成长段；若目标包是长复句推演风，则保持多重复句连贯推演。
3. 根据本次待写/待改文稿的场景类型，读取对应的 `指纹/*.md` 模块，提取**句法配方**与**场景推进结构**。

### 第二步：调取“正向替换词句库（`lookup`）”与 3~5 个匹配的原文黄金场景切片（`slice`）
1. **调取正向替换词句弹药库（顶替 AI 默认词库）**：
   - 运行 `python "<SKILL_DIR>/scripts/novel_pack.py" --json-out .work/lookup.json lookup --pack <包路径> --query "<本章核心冲突/场景关键词>"`，或直接读取写作包的 `词句库/词汇库.md`（11类原著实感词与新书设定转换槽）、`词句库/衔接库.md`、`词句库/句段库.md`、`词句库/声线卡.md`。
   - **正向替换铁律**：写作时主动使用库中的**原著动词、眼神词、神态词、言语导引词与转折衔接词**，替代大模型高频腻子词；跨题材调用时，严格按【新书设定转换槽】将原著体系词（如蛊虫/元石/仙窍）转换为当前作品设定（如法器/灵石/气海或银两/账册），绝不漏出原著专名（`check_novel_ai.py` 会拦截 `pack-world-term-leak`）。
   - **声线卡防串味**：对照 `词句库/声线卡.md`，为场内不同地位角色分配不同句长与语气特征（上位者短促祈使/打断，算计者设问与条件交换），严禁全员同一腔调（`check_novel_ai.py --narrative-check` 会拦截 `voice-card-homogeneity`）。
2. **调阅 3~5 个最接近本次场景的原文黄金切片**：
   - 运行 `python "<SKILL_DIR>/scripts/novel_pack.py" --json-out .work/slices.json slice --pack <包路径> --scene S001 S002` 精读原文。
   - **校准目标**：体会目标作者的真实句子呼吸感、切入角度与留白分寸；**只学其叙事机制与节奏，严禁照抄切片里的具体造句或无关环境物象**。

### 第三步：读反AI检测核心规范与通用指纹
1. 读 `references/anti_ai_core.md`：掌握八大 AI 统计与叙事病灶拦截准则。
2. 读 `references/通用指纹/告知词禁忌.md`：五类告知词（程度副词、情绪词、多余身体部位、模糊形容词、口头禅过渡词）在叙述里换成具体动作、特征与数量。
3. 本章有换时间、换地点、换视角或插入回忆时，读 `references/通用指纹/转场技法.md`。

## 二、核心边界：什么必须锁死？什么必须重构？

| 维度 | 🔒 必须 100% 锁死的底线（Hard Lock） | 🛠️ 必须按目标写作包重构的对象（Craft Upgrade） |
| --- | --- | --- |
| **叙述人称与视角** | **叙述人称跟随原稿**：第三人称原稿绝对禁止改成第一人称（“我”）自述（仅对白 `“……”` 或带引号的角色直接独白内可用“我”）；第一人称原稿保留第一人称，不得擅自改成第三人称。保持原稿的核心视角归属 | 严守视角限知边界：次要角色只写其外部动作与话语，严禁旁白随便钻进配角脑子里替其解释苦衷或全盘剧透动机 |
| **专名、台词与原意** | 全部人名、地名、功法/系统提示框（`【……】`）、古籍引文、核心账目/修为数字、各方知情边界与结局走向；**原稿中原本就自然传神的核心对白可直接保留** | 重写说明文式的生硬台词；算账只抓 1 个决定生死的核心差额，严禁连续罗列 3 项以上带精确数字的物资清单（拒绝游戏背包报菜名） |
| **推理与悬念留白** | 原稿的核心破局逻辑与伏笔锚点 | **推演“三分留一”**：主角算账或看破破绽时，只点出眼前的 1 个反常物证/数字矛盾并立刻接行动，严禁在脑内把整盘棋局的前因后果全量讲透；写内鬼或伪装只写外部动作，严禁贴 `假意/状似无意/眼底深处掠过` 等剧透标签 |
| **段落结构与标点** | 真实因果时间线与核心戏剧转折 | 破除“首段报天气+报主角简历”开篇、监控摄像头式过场动作链、章末写景打卡；**严禁“角色说完信息→旁白单起一行复述加感叹号”的回声虫写法**；严禁无因果的周期性景物节拍器（如每隔几段写一次药炉/炭火） |
| **情绪与词汇层** | 人物此刻的真实处境压力与态度决断 | 铲除高危 AI 腻子词、生理通感比喻、高频生理套话（`深吸一口气/瞳孔骤缩/抠进掌心`）、对比开场套话（`寻常人…但主角不同`）、翻案句（`不是A而是B / X不代表不能Y`）以及四字套路成语轰炸 |
| **篇幅与信息密度** | 原稿的每个剧情事件、因果转折与结局都要以场景写出来，不能压成一句梗概；严禁凭空捏造原稿不存在的支线角色或无关剧情注水 | **篇幅不设目标比例**：不推动剧情的废话、重复交代、无阻力过场该删就删；门禁只拦高于原稿 `1.60` 倍或低于 `0.40` 倍的极端情况 |

## 三、模式 A：保剧情深度改写流程

### Step 1：梳理场景节拍与锁死清单
通读用户原稿，锁定不可更改的角色专名、核心数字、系统面板/引文、因果顺序与章末悬念落点；识别原稿中拖沓的开篇简历、琐碎过场链条、全知剧透解释和 AI 套词。

### Step 2：按目标写作包句段基线与反检测准则成稿
1. **开篇切入**：避开“天气+外貌简历”堆砌和“寻常人如何、但主角不同”的套话，直接从具体冲突、反常器物或人物交锋切入。
2. **句段呼吸服从目标写作包 `stats.json`**：
   - 严格对齐目标包的叙述句均值与单句成段率；
   - 同一人连续行动时大量采用**承前省略主语**，避免段段以“他/她/主角名”打头；
   - 叙述正文破折号 `——` 清零，对白统一使用中文引号 `“…”` 或 `「…」`，叙述段尾克制使用感叹号 `！`。
3. **推演留白与去套路化**：
   - 砍掉动作后的旁白解释尾巴，不替读者总结陈词；
   - 不写任何脱离主线因果的硬塞闲笔，不重复拿同一环境道具当节拍器；
   - 将四字套路成语拆解为大白话的具体利益后果，避免同词近距复读。
4. **章末收束**：在核心悬念、新危机揭晓或关键决断处果断停笔，严禁章末写景打卡或预告片式升华。

### Step 3：运行 `check_novel_ai.py --narrative-check` 双层门禁
```bash
python "<SKILL_DIR>/scripts/check_novel_ai.py" <改写稿.md> --source <用户原稿.md> --pack <目标写作包路径> --narrative-check --output .work/ai_check.json
```
- 确认 `STATUS=PASS`（`BLOCKING=0`）即可交付！
- 若有 `blocking` 项，使用 `edit` 工具定点修复报错段落（如删去剧透标签、合并报菜名数字、消除感叹号复读、恢复目标包单句成段率等），重跑确认通过。
- 若输出 `STATUS=ERROR`（例如 `--pack` 路径写错），先修正路径再重跑，不得当作通过。
- 若原稿存在剧情矛盾或数字漏洞，在正文后另起 `## 附：原稿剧情与逻辑优化建议` 供作者参考。

## 四、模式 B：章节纲要转正文流程

1. **审阅纲要与确认关键分歧点**：纲要已定的事件、手段、胜负与章末落点直接锁定；仅在缺失核心动机、核心破局机制或结局走向时给 2~3 个简短方案请作者拍板。
2. **拆解节拍表（Beat Sheet）**：拆分为 3~6 个场景节拍，确保每场戏结束时筹码、信息、伤势或局势发生实质推进。
3. **全程第三人称套用写作包配方下笔**：严格遵循目标写作包 `PACK.md` 的句段呼吸与场景推进结构，遵守 `anti_ai_core.md` 与 `告知词禁忌.md`。
4. **运行双层门禁校验**：
   ```bash
   python "<SKILL_DIR>/scripts/check_novel_ai.py" <成稿.md> --pack <目标写作包路径> --narrative-check --output .work/ai_check.json
   ```
   确保 `STATUS=PASS`（`BLOCKING=0`）后交付正文。

## 五、模式 C：按写作包审阅与全量逐条删改流程（Review Mode）

当用户要求“按照某某写作包审阅/审查/诊断”某篇文稿（而非直接全文改写）时，**绝对禁止把零信息量的 AI 废话拿去换词保留，绝对禁止脱离写作包词库写出 `话音微顿/抬眼觑着` 等 AI 腔改写建议，也绝对禁止未对改写建议做门禁自检就直接交付**！

### Step 1：先读写作包词库与指纹 + 必跑 `check_novel_ai.py` 提取 `review_items`
1. 先读取目标写作包的 `PACK.md`、`词句库/词汇库.md`、`词句库/衔接库.md`、`词句库/声线卡.md` 及对应 `指纹/*.md`；
2. 运行：
   ```bash
   python "<SKILL_DIR>/scripts/check_novel_ai.py" <待审稿.md> --pack <目标写作包路径> --narrative-check --output .work/ai_review.json
   ```
3. 读取 `.work/ai_review.json` 中的 `blocking`、`warnings`、`narrative_architecture` 以及 **`review_items` 全量逐段定位清单**。

### Step 2：按五大板块输出《全量逐条审阅与删改报告》（先砍废话，再改词与升级）

1. **板块一：量化基线与门禁总览**
   - 对比待审稿与目标写作包 `stats.json` 的核心指标（叙述句均值、单句成段率、对白占比、门禁状态）。
2. **板块二：必删 AI 废话与注水句清单（只删不改，直接抹除）**
   - 专门揪出全文所有**不推进剧情、不提供新信息、纯属 AI 凑字数的废话句和废话分句**：
     - 心理播报导语（如 `在心中默默盘算起来`、`他暗自思索了一番`、`一个念头在脑海中浮现`）；
     - 镜头报幕与论文垫片词（如 `入目处，`、`定睛一看，`、`毫无疑问，`、`显而易见，`）；
     - 动作/台词后的动机说明书尾巴（如 `，以此来掩饰……`、`，显然是为了……`、`，这也就意味着……`）；
     - 情绪/处境二次抽象总结句（如前文已演完剧痛，后文又总结 `这种剧痛让他几乎晕厥`）；
     - 周期性环境节拍器动作（如对话间反复 `拿起竹夹拨了拨炉底暗炭`、`看了一眼药炉`）；
     - 对白里向当事人背诵其自身已知简历的废话（如丫鬟对主人说 `您昔日乃是紫府巅峰，天纵少爷既承了您的神雷体与雷泽气海……`）。
   - **处理铁律**：以上废话**一律整句或整截直接删除，绝不允许同义改写保留**！每条标明 **【第N段原句】→【为什么是AI废话】→【直接删除后的干净段落】**。
3. **板块三：门禁红线与叙事病灶逐处改写（100% 全覆盖）**
   - 将所有 `blocking` 与核心 `advisory`（如无引号第一人称越界、剧透式眼神/演技标签、翻案句、连续等长段落区间等）逐条列出，每条给出 **【第N段原句】→【诊断】→【可直接复制替换的改写建议】**。
4. **板块四：去 AI 味词汇、微动作尾巴与告知词全量替换表（强制查表使用 `词句库/词汇库.md`）**
   - 将 `review_items` 扫出的每一处 AI 腻子词、换称呼简历腔、微动作尾巴（每一处 `了一下/了一眼/叹了口气`）、五类告知词全部列出，**必须从目标写作包 `词句库/词汇库.md` 中选取高频原著实感词**，逐处给出 **【第N段原句】→【可直接复制替换的改写建议】**。
5. **板块五：对齐目标写作包（`R001~Rxxx`）的顶级质感升级点（每条必附完整重写段落）**
   - 挑出待审稿中尚未发挥出目标写作包顶级质感的 3~5 个关键段落，对照写作包规则 `R001~Rxxx` 与 `词句库/声线卡.md` 诊断后，每一条都必须附上 **【可直接复制替换的改写建议】**。

### Step 3：对审阅报告中的【改写建议】运行 `--extract-suggestions` 门禁自检（未过严禁交付）
在将审阅报告发给用户前，必须把审阅报告存入 `.work/review_draft.md`，运行：
```bash
python "<SKILL_DIR>/scripts/check_novel_ai.py" .work/review_draft.md --extract-suggestions --pack <目标写作包路径> --narrative-check
```
- 脚本会自动提取报告里所有的 `【可直接复制替换的改写建议】` 区块，检验模型自己写的改写建议是否夹带了 `抬眼觑着`、`话音微顿`、`下意识`、周期性 `炭火/药炉`、叙述句尾感叹号 `！` 等 AI 病灶，并统计其命中目标写作包正向词库（`LEX_HITS`）的数量。
- **只有当 `--extract-suggestions` 输出 `STATUS=PASS`（`BLOCKING=0`）时，才可将审阅报告交付给用户！**
