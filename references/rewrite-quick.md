# 写作包改写：轻量流程

这是普通改写/按纲创作的短流程。它优先保护自然成文，不要求把正文改到某个统计数字。

## 1. 只读取当前场景需要的材料

- `PACK.md`、`stats.json`
- 命中场景的 1～2 个 `指纹/*.md`
- 2～3 个相关 `scenes.jsonl` 切片
- 按场景关键词运行一次 `lookup`

不要为了改一章正文把 `lexicon.json`、`rules.jsonl` 或全部反 AI 文档塞进上下文。只有检查报告命中某条规则时，才按需打开对应小节。

## 2. 先写自然初稿

- 改写跟随原稿人称；按纲创作使用第三人称。
- 保留人物关系、专名、关键数字、因果和结局。
- 写作包只提供叙事节奏、视角、对白博弈和场景调度参考。
- 不追求词库命中数、句长均值或某个“AI 分数”；不为命中词库硬塞生词、成语或目标作品专名。
- 不把原稿每个句子都换一遍，也不把正常的天气、比喻、重复和对白统一抹平。

## 3. 检查只跑一次，先看严重程度

```bash
python "<SKILL_DIR>/scripts/check_novel_ai.py" <成稿.md> \
  --source <原稿.md> --pack <写作包路径> --narrative-check \
  --output .work/ai_check.json
```

事实账本是可选的。默认只报告账本缺失/冲突，不强迫改写成账本原句；只有账本经过人工核对且确实要严格执行时，才追加 `--fact-lock-strict`。

优先处理：

- `STATUS=ERROR`
- 人称越界、跨书设定泄漏、整句照搬、明显语病
- 明确的事实冲突（人工确认后再改）

谨慎处理：

- `pack-lexicon-*`、句长/段落形状、情绪密度、对白说教比例、微动作和高频词提醒
- 单个天气、比喻、成语或身体动作命中

这些项目不能单独证明文本有问题。若改动会让角色声线、信息节奏或自然表达变差，保留原句，并在交付说明中记录该提醒。

## 4. 最多做一次定点复核

只改确认有问题的局部，不为清零 warnings 全文重写。复核后通读一遍，优先相信语义、人物声线和场景因果，而不是 `PASS` 这个标签。
