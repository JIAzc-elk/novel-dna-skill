# 叙事架构层去AI味核心规范 v2.0（频率控制版）

> **核心思想**：不是"完全禁止"，而是"控制比例到人类基线"。基于StoryScope(arXiv:2604.03136)论文的叙事统计指纹。

---

## 零、为什么采用"频率控制"而非"完全禁止"

根据StoryScope论文实测，**人类作者也会使用这些手法**，只是频率远低于AI：

| 特征 | 人类基线 | AI基线 | 控制目标 |
|------|---------|--------|---------|
| 对话讨论哲学 | 34% | 59% | ≤35% |
| 无支线单线推进 | 57% | 79% | ≤60% |
| 主题被直接讲出 | 52% | 77% | ≤55% |
| 角色通过决定闭环 | 46% | 69% | ≤50% |
| 身体感官堆砌 | 38% | 81% | ≤40% |

**"完全禁止"的三大问题**：
1. 会让文字矫枉过正（为了躲避规则而产生新的机械腔）
2. 无法量化检测（check_novel_ai.py无法准确拦截）
3. 与写作包规则可能冲突（某些场景需要直接表达）

---

## 一、对话分类控制（最关键）

### 检测标准
**统计本章所有对话段，计算说教式对话占比**：

```python
说教式对话 = 包含以下特征的对话段：
- 讨论"意义/道理/真正的XX/所谓的XX"
- 连续3句以上讨论同一抽象概念
- 角色直接说出内心变化（"我明白了X"）

说教式比例 = 说教式对话数 / 总对话段数
```

**控制目标**：≤35%（人类基线34%）

### 修复方法
当比例>35%时，**选择超额部分的对话进行以下改写**：

1. **改为动作**
   ```
   ❌ "这次失败让我明白，真正的强大来自内心。"
   ✅ 他攥紧剑柄，没说话。
   ```

2. **改为不完整的话+停顿**
   ```
   ❌ "什么是勇气？勇气就是明知不可为而为之。"
   ✅ "怕吗？""怕。"他顿了顿，"但我得去。"
   ```

3. **改为答非所问**
   ```
   ❌ "我终于明白了坚持的意义。"
   ✅ "外面开始下雨了。"（转移话题）
   ```

### 重要说明
- **不是删除所有说教式对话**，而是将比例降到35%以内
- **师徒传道、哲学辩论场景可保留**，但要控制全章总体比例
- **功能性说教**（推动剧情/建立世界观）优先保留

## 二、情绪呈现分级控制

### 检测标准
**统计每万字的情绪直述密度**：

```python
情绪直述 = 包含以下模式的句子：
- 直接命名情绪："很愤怒/悲伤/震惊/失望"
- 情绪涌现："心中涌起一股XX"
- 情绪形容："语气充满了XX"

情绪直述密度 = 情绪直述句数 / (总字数/10000)
```

**分级标准**：

| 密度 | 级别 | 处置 |
|------|------|------|
| 0-2处/万字 | 绿区 | 可接受（人类基线约3-5处） |
| 3-5处/万字 | 黄区 | 建议改为动作/生理反应 |
| >5处/万字 | 红区 | 必须修复到黄区以内 |

### 修复方法

**红区问题（必须改）**：
```
❌ "他非常愤怒地看着她"
✅ "茶杯砸在地上，他没看碎片"

❌ "心中涌起一股悲伤"
✅ "她盯着窗外，手指抠进掌心"
```

**黄区问题（建议改）**：
- 高潮场景的情绪直述可保留（如"他怒了"）
- 但密集的情绪堆砌必须用动作分散

## 三、段落结构弹性控制

### 检测标准
**检测连续5段的结构特征**：

```python
# 检查1：段落字数标准差
段落字数 = [187, 191, 185, 189, 192]
标准差 = 2.8

# 检查2：段落开头句式
段落开头 = ["林峰发现", "林峰意识到", "林峰明白"]

# 检查3：工整结构密度
工整段 = 连续3段都是"情况→分析→结论"
```

**分级标准**：

| 问题 | 阈值 | 级别 |
|------|------|------|
| 段落字数标准差<5 | 必须修复 | blocking |
| 连续3段同一开头 | 必须修复 | blocking |
| 连续3段工整结构 | 建议打散 | advisory |

### 修复方法

**blocking问题（必须改）**：
```
❌ 段落字数：[187, 191, 185, 189, 192]（标准差2.8）
✅ 改后：[187, 85, 245, 120, 189]（标准差>8）
方法：第N段拆成两短段，第N+1/N+2合并成长段
```

**advisory问题（可选改）**：
- 战斗场景的连续短段可保留（符合节奏需要）
- 推理场景的工整段落可保留（符合思维展开）

## 四、支线细节渗透率控制

### 检测标准
**统计每10段的支线细节密度**：

```python
支线细节 = 不推进主线的细节：
- 环境中的无关物件（≤15字）
- 角色的无意识小动作
- 旁观者的反应
- 意外的小插曲

支线细节密度 = 支线细节数 / (总段数/10)
```

**控制目标**：≥3处/10段（即每3-4段至少1处）

### 注入方法

**合格示例**：
```
正在谈判时：他瞥见墙角有只蜘蛛在结网。（15字，不推进剧情）
战前准备：他下意识摸了摸腰间的玉佩。（无意识动作）
主角离开时：门口卖糖葫芦的小贩缩了缩脖子。（旁观者）
```

**注入原则**：
- **不能推进主线**（否则不是支线细节）
- **不能超过15字**（否则喧宾夺主）
- **不能连续出现**（至少间隔2-3段）
- **高潮段可豁免**（紧张时刻不适合插入）

## 五、句长节奏目标控制

### 检测标准（R000优先级规则）

**检测连续10句叙述句**：
```python
句长序列 = [15, 18, 42, 7, 23, 19, 38, 11, 25, 16]
标准差 = calculate_std(句长序列)
```

**分级标准**：

| 标准差 | 级别 | 处置 |
|--------|------|------|
| >10 | 优秀 | 节奏自然 |
| 8-10 | 良好 | 达标 |
| 5-8 | 黄区 | 建议改进（advisory）|
| <5 | 红区 | 必须修复（blocking）|

### 修复方法

**红区问题（必须改）**：
```
❌ 句长序列：[18, 20, 19, 21, 18, 20, 19, 21, 18, 20]
   标准差=1.2（严重过低）

✅ 修复方法：
- 将第3句（19字）拆成两句：一句7字+一句12字
- 将第7、8句合并成一句40字的复杂句
- 改后：[18, 20, 7, 12, 21, 18, 40, 18, 20]
- 新标准差=9.5（达标）
```

**黄区问题（建议改）**：
- 《蛊真人》这类长复句风格，标准差7-8也可接受
- 关键是有极端值：至少1句<10字 + 1句>40字

### 与写作包规则的关系

```
场景  | 写作包要求均句长 | R000要求标准差 | 执行方式
-----|-----------------|---------------|----------
战斗 | 18字（短促风）  | >8            | 保持18字均值，但插入5字落槌句+35字回合描述
推理 | 36字（长复句）  | >8            | 保持36字均值，但插入15字转折句+50字推演句
```

## 七、场景因果完整性检查（人工核查）

> **来源**：改编自 fiction-humanizer-zh 的 scene-rewrite.md "单场景6步法"

### 检查标准

每个核心场景（冲突/反转/爽点/重要对话）必须包含6个要素：

#### 1. 场景功能明确
这场戏要达成什么？

**合格示例**：
- 建立关系（主角与盟友建立信任）
- 暴露秘密（敌人发现主角身份）
- 制造误会（女主误解男主意图）
- 升级冲突（从口角升级到生死对决）
- 兑现爽点（主角反杀嘲讽者）
- 埋伏笔（看似无关的物件为后续做铺垫）
- 让人物付代价（为上一场的选择付出后果）

**❌ AI常犯错误**：场景只是"发生了"，没有明确改变什么
```
❌ 林峰和师父谈了一会儿，然后回去修炼了。
✅ 林峰从师父的沉默中察觉到试炼可能不止表面那么简单（建立悬念）
```

#### 2. 人物目标具体
主角想要什么？对手想阻止什么？旁观者能改变什么？

**❌ AI常犯错误**：人物只是"在场"，没有具体欲望
```
❌ 林峰参加了拍卖会。（人物是布景板）
✅ 林峰必须在拍卖会上拿到那颗丹药，哪怕倾家荡产。（目标明确）
```

#### 3. 压力来源清晰
压力必须来自具体约束，而非空泛危机感：

**合格压力源**：
- 时间：天亮前必须离开城池
- 身份：被认出就会暴露卧底身份
- 金钱：买下此物就会断粮三个月
-伤病：旧伤未愈，强行运功会经脉尽断
- 舆论：此事传出去，家族颜面扫地
- 权力：对方是长老，当众顶撞就是死罪
- 亲情：救她就要背叛兄弟
- 证据：销毁此物就再也查不清真相
- 空间限制：窄巷无法躲避，只能硬接

**❌ AI常犯错误**：冲突凭空出现，没有前置压力
```
❌ 敌人突然来袭。（为什么现在？为什么这里？）
✅ 敌人在主角最虚弱的时候来袭（旧伤未愈+孤立无援）
```

#### 4. 至少一次失败
人物必须经历以下至少一种挫折：

- 判断不准（以为敌人只有一人，结果是三人）
- 话说错（本想试探，结果暴露了破绽）
- 证据不够（本想揭发对手，但证据链有漏洞）
- 动作慢半拍（招式被看穿，险些丧命）
- 代价超出预期（成功逃脱，但失去了珍贵信物）

**❌ AI常犯错误**：主角一路顺风，没有代价
```
❌ 林峰很快想到办法，成功化解危机。
✅ 林峰第一次尝试被识破，损失了一枚保命符，第二次才险胜。
```

#### 5. 转折有铺垫
转折必须来自前文信息，不凭空救场。

**合格转折**：
- 主角用了第3章埋下的暗棋
- 对手的弱点在第8章被旁观者提过一嘴
- 看似无用的道具在此刻派上用场

**❌ AI常犯错误**：靠系统/救兵/对手降智解决
```
❌ 就在千钧一发之际，师父突然赶到。（无铺垫救场）
✅ 林峰捏碎了师父临行前给的玉符（第2章埋过）
```

#### 6. 余波可见
场景结束后，以下至少有一项改变：

- 人物关系：称呼变化、开始避开目光、刻意客气
- 资源变化：损失灵石、消耗保命符、欠下人情
- 心理变化：不再信任某人、开始怀疑自己选择
- 外部局势：势力关系翻转、秘密被第三方知晓

**❌ AI常犯错误**：冲突结束后恢复原状，没有影响
```
❌ 两人吵完后，下一段又正常对话了。
✅ 两人吵完后，对话变得公式化，不再称呼对方名字。
```

### 检查方法

**本项由作者人工核查**，check_novel_ai.py不检测（因果链难以用统计方法判断）

每写完一章，按6要素逐个核对核心场景（通常2-4个）：

```markdown
## 场景因果完整性自查清单

场景名称：__________（如"主角首次对抗长老"）

- [ ] **场景功能**：这场戏明确达成了什么？（写出具体改变）
- [ ] **人物目标**：主角想要什么？对手想阻止什么？（至少2个具体目标）
- [ ] **压力来源**：压力来自哪里？（至少1个具体约束）
- [ ] **失败点**：人物经历了什么挫折？（至少1次）
- [ ] **转折铺垫**：转折来自哪一章的哪个信息？（必须可追溯）
- [ ] **余波体现**：本场景后什么改变了？（至少1项可观察改变）

如有任一项答"无"或"不明确"，则本场景需要补充或重写。
```

### 典型案例对照

#### 案例1：从"事件发生"到"场景完整"

```markdown
❌ 原稿（6要素缺失5个）：

林峰参加了拍卖会。他看中了一颗丹药，于是竞价拿下。
拍卖会结束后，他回到客栈休息。

【分析】：
✗ 场景功能：不明确（只是记流水账）
✗ 人物目标：不明确（为什么要这颗丹药？）
✗ 压力来源：无
✗ 失败点：无
✗ 转折：无
✗ 余波：无

---

✅ 改后（6要素完整）：

林峰攥紧了怀里仅剩的三百灵石。【压力：金钱约束】
那颗养元丹是母亲活命的唯一机会，今天拿不到，就真的来不及了。【目标+时间压力】

"三百！"他举牌。
"五百。"对面包厢传来慢悠悠的声音。【失败点1：被碾压】
林峰咬牙："六百！"
"哦？"那人笑了，"八百。"

林峰手抖了。他只有三百灵石。【代价暴露】
他犹豫了三秒，摘下了祖传的玉佩，递给拍卖师："这抵五百，加我的三百灵石，够吗？"【转折：用前文提过的玉佩】

拍卖师看了一眼，点头："够。"
对面包厢沉默了。

林峰拿到丹药时，手还在抖。【余波：资源损失+心理变化】
他出门时，瞥见那个包厢的门半开着，里面坐着的人……是二叔。【余波：关系变化+新悬念】
```

#### 案例2：从"爽点宣布"到"爽点呈现"

```markdown
❌ 原稿（缺失要素：失败点、余波）：

林峰展示出真实实力，所有人都震惊了。
他成功证明了自己，赢得了大家的尊重。

---

✅ 改后（补充失败+余波）：

"你只是筑基初期，也敢叫板？"长老冷笑。【压力：实力差距+权力压制】
林峰没说话，掌心亮起第二道灵光。【失败点铺垫：他原本只想亮一道】

静了一瞬。
第三道。第四道。

有人吸了口气。
长老的笑僵在脸上。【余波1：对手态度变化】

"四道灵根……"有人低声说。
"不对，他上个月还是两道。"【余波2：产生新的疑问】

林峰收手，指尖还在微微发烫。强行催动未稳定的灵根，至少要修养三天。【余波3：付出代价】
但够了。他转身，看向长老："还有问题吗？"

长老没说话。【余波4：权力关系微妙变化】
```

---

### 重要说明

1. **不是每个场景都要严格遵守6要素**
   - 过渡场景（主角赶路、日常对话）可以只有2-3个要素
   - 但核心场景（推动剧情的关键转折）必须完整

2. **6要素不是线性顺序**
   - 可以"先失败→再明确目标→寻找压力突破口"
   - 顺序灵活，但要素齐全

3. **本规则优先级低于前5项**
   - 如果场景已通过前5项检测（对话比例、情绪密度、段落节奏等），但缺少某个要素，属于advisory级别
   - 只有场景完全无功能（6要素全缺）才是blocking级别

## 八、典型案例对照

### 案例1：对话从"说教式"到"功能式"

```markdown
❌ 原稿（说教比例58%，超标）：
"林峰说：'这次失败让我明白，真正的强大来自内心的坚持。'"
"师父点头：'对，只有内心强大，才能战胜一切困难。'"
"林峰继续说：'我以后会记住这个道理。'"

✅ 改后（说教比例28%，达标）：
林峰攥紧剑柄，没说话。
师父等了一会儿，见他没说，点了点头，转身走了。
林峰站在原地，攥着的拳头慢慢松开。
```

**改法说明**：
- 3段对话全是说教（100%） → 改为0段说教（0%）
- 但这不是目标，目标是**本章整体说教比例≤35%**
- 如果本章其他地方还有功能性对话，这里全改为动作也可以

### 案例2：情绪从"直述"到"呈现"

```markdown
❌ 原稿（情绪直述密度12处/万字，红区）：
她非常愤怒地盯着他，心中涌起一股难以抑制的怒火。
她感到十分失望，语气充满了悲伤。
他震惊地看着这一切，简直不敢相信自己的眼睛。

✅ 改后（情绪直述密度0处/万字，绿区）：
她盯着他，手指抠进掌心。指甲嵌进肉里，不疼。
茶杯砸在地上。她没看碎片。
他张了张嘴，半天没声。
```

### 案例3：段落从"工整"到"参差"

```markdown
❌ 原稿（连续5段，标准差2.1）：
林峰发现对手很强。他仔细分析对方的弱点。他决定从侧翼进攻。（187字）
对手反应很快。每次攻击都被化解。林峰意识到正面突破不可行。（191字）
局势越来越不利。时间拖得越久越危险。他必须尽快做出决断。（185字）
…（后续3段也都185-192字）

✅ 改后（标准差9.8）：
林峰试探性地刺出一剑。
对手侧身，剑尖擦过衣角。快！
他没收招，顺势变刺为扫——空了。对手已经退开三步。（85字）

墙角有只蜘蛛在结网。（支线细节，12字）

林峰喉咙发紧。不能再拖。他深吸一口气，剑势突然一变，从中路直刺对方咽喉。对手这次没能完全躲开，衣领被划开一道口子。布料撕裂的声音在静默中格外刺耳。（245字）
```

## 九、与写作包规则的优先级关系

### 优先级公式

```
BLOCKING级别的R000 > 写作包R001-R016 > ADVISORY级别的R000 > 通用指纹
```

### 冲突解决案例

**场景**：写作包要求"均句36字"（长复句推演风），但R000要求"标准差>8"

**解决方法**：
1. 保持推演段落用40-45字长句
2. 但每10句插入至少1句<10字的落槌句
3. 最终：均值36字（符合写作包），标准差9.2（符合R000）

**不应该的做法**：
- ❌ 为了拉高标准差，把所有句子改成5字/50字交替（失去写作包风格）
- ❌ 为了保持均句36字，全部都写35-37字（违反R000）

## 十、常见问题

**Q1: 为什么不完全禁止"对话讨论道理"？**
A: 因为人类作者也有34%的对话是这样的（师徒传道、哲学辩论等场景）。完全禁止会让对话变得不自然。

**Q2: 标准差<8但接近8（如7.5），必须改吗？**
A: 不必须。7.5属于黄区（advisory），建议改进但不阻断。只有<5才是blocking。

**Q3: 高潮场景可以直接写"他怒了"吗？**
A: 可以，但要控制**全章密度**。偶尔的直接表达不影响，密集堆砌才是问题。

**Q4: 支线细节在战斗高潮段也必须插入吗？**
A: 不必须。高潮段可豁免，在其他段落补够密度即可。

**Q5: 改完后check_novel_ai.py还是有advisory提示怎么办？**
A: advisory只是建议，不阻断交稿。按语境判断是否需要改进。

## 十一、检测脚本实现示例

```python
# check_novel_ai.py 新增功能

def check_dialogue_ratio(text):
    """检测对话说教比例"""
    dialogues = extract_dialogues(text)
    preaching = [d for d in dialogues if is_preaching(d)]
    ratio = len(preaching) / len(dialogues) if dialogues else 0
    
    if ratio > 0.35:
        return {
            "severity": "blocking",
            "metric": "对话说教比例",
            "value": f"{ratio:.1%}",
            "threshold": "35%",
            "suggestion": f"需改{len(preaching) - int(len(dialogues)*0.35)}处对话"
        }
    return None

def is_preaching(dialogue):
    """判断对话是否为说教式"""
    keywords = ["意义", "道理", "真正的", "所谓的", "明白了"]
    abstract_count = sum(1 for kw in keywords if kw in dialogue)
    return abstract_count >= 2 or "这说明" in dialogue or "这告诉" in dialogue

def check_gratification_announcement(text):
    """检测爽点直接宣布（v2.1新增）"""
    patterns = [
        r"所有人都(?:震惊|惊呆|愣住|傻眼)了",
        r"(?:他|她)终于(?:逆袭|翻身|成功|证明)了",
        r"这是属于(?:他|她)的(?:高光|荣耀|胜利)时刻",
        r"全场(?:寂静|沸腾|哗然)",
        r"(?:众人|所有人|全场)(?:都|全部|纷纷)(?:震惊|惊讶|佩服|折服)",
    ]
    
    hits = []
    for pattern in patterns:
        matches = re.findall(pattern, text)
        hits.extend(matches)
    
    if len(hits) > 0:
        return {
            "severity": "blocking",
            "metric": "爽点直接宣布",
            "count": len(hits),
            "samples": hits[:3],
            "fix": "不宣布爽，让读者从对手反应、现场静默、利益翻转里感到爽"
        }
    return None

def check_synopsis_mode(text):
    """检测剧情梗概冒充正文（v2.1新增）"""
    patterns = [
        r"(?:于是|然后|接着|随后|紧接着)[，,][^。！？]{5,30}(?:决定|意识到|明白了|发现)",
        r"(?:他|她)[^。！？]{5,20}(?:很快|马上|立刻|随即)[^。！？]{5,20}(?:成功|解决|找到|揭穿)",
        r"在[^。！？]{3,10}(?:之后|以后|过后)[，,][^。！？]{10,30}[。！？]",
    ]
    
    hits = []
    for pattern in patterns:
        matches = re.findall(pattern, text)
        hits.extend(matches)
    
    chars = max(1, len(re.sub(r"\s", "", text)))
    density = len(hits) * 10000 / chars
    
    if density > 8:
        return {
            "severity": "advisory",
            "metric": "剧情梗概密度",
            "density": f"{density:.1f}处/万字",
            "threshold": "8",
            "samples": hits[:3],
            "fix": "拆成触发、尝试、阻碍、再尝试、代价"
        }
    return None
```

## 总结

**频率控制 vs 完全禁止**：

| 维度 | 频率控制（v2.0） | 完全禁止（v1.0） |
|------|-----------------|-----------------|
| 理论依据 | StoryScope论文人类基线 | 主观判断 |
| 可量化性 | ✅ 可精确检测 | ❌ 难以量化 |
| 误伤率 | 低（允许合理使用） | 高（一刀切） |
| 与写作包兼容 | ✅ 优先级明确 | ❌ 可能冲突 |
| 可维护性 | ✅ 阈值可调 | ❌ 规则僵化 |

**核心原则**：
1. 不追求"零AI味"，追求"接近人类基线"
2. 分级处理：blocking必须改，advisory建议改
3. 频率控制：每条规则都有阈值，不是零容忍
4. 功能优先：承担叙事功能的写法可保留
